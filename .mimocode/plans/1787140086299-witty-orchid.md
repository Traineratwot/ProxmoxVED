## Issues to fix

### 1. `truncate: cannot open '' for writing` (Step 1/7)
**Root cause:** In `create_new_volume()` line 383, `pvesm path` is called for a volume that doesn't exist yet. The command fails silently (`2>/dev/null`), returning empty string. `truncate -s "$new_size" ""` then fails with the confusing error.

**Fix:** Add validation after `pvesm path` — if `storage_path` is empty, log the actual `pvesm path` error and return 1 with a clear message.

### 2. Silent crash at Step 3/7 (Copying data)
**Root cause:** `copy_data` runs `dd` but errors may be swallowed. The `set -eE` should catch this, but the dd command's stderr goes to the spinner which may hide it. Also, `get_device_path` may return empty strings if the volume lookup fails.

**Fix:** 
- Add explicit validation that `source_dev` and `dest_dev` exist and are block devices before calling `copy_data`
- Add a wrapper around `copy_data` that captures and displays dd errors
- Add error checking after `verify_checksum` to display actual hash mismatch details

### 3. Use api.func / error_handler.func helpers
The script currently defines its own `msg_info`, `msg_ok`, `msg_error` functions. Per the user's request, adopt the project pattern:
- Source `api.func` for telemetry (init_tool_telemetry)
- Source `error_handler.func` for catch_errors
- Use the standard color variables from the project (YW, GN, RD, BL, CL)
- Remove custom msg_* functions (they'll come from error_handler.func)

However, looking at the existing PVE tools (fstrim.sh, lxc-delete.sh), they do NOT source error_handler.func — they define their own minimal helpers. The addon template sources core.func + tools.func. 

**Decision:** Follow the existing PVE tools pattern — keep self-contained with consistent colors, but add proper error trapping via a local ERR trap that displays errors clearly. This is a PVE host tool, not an addon, so it doesn't need the full addon framework.

## Changes

### A. Add error trap (after set -eEuo pipefail, ~line 12)
Add an ERR trap that displays the failing command, line number, and exit code clearly:

```bash
error_handler() {
  local exit_code=$?
  local cmd="${BASH_COMMAND:-unknown}"
  local line="${BASH_LINENO[0]:-unknown}"
  echo -e "\n${RD}[Error]${CL} in line ${line}: exit code ${exit_code}"
  echo -e "${RD}[Error]${CL} Command: ${cmd}"
  log "ERROR exit=$exit_code line=$line cmd=$cmd"
  allow_interrupts
  exit "$exit_code"
}
trap error_handler ERR
```

### B. Fix `create_new_volume()` — dir/nfs/cifs branch (lines 381-386)
- After `pvesm path`, check if `storage_path` is empty
- If empty, run `pvesm path` again WITHOUT `2>/dev/null` to capture the actual error
- Display the error and return 1

```bash
dir|nfs|cifs)
  local new_vol="vm-${ctid}-disk-new.raw"
  local storage_path
  storage_path=$(pvesm path "${storage}:${new_vol}" 2>/dev/null)
  if [[ -z "$storage_path" ]]; then
    local pvesm_error
    pvesm_error=$(pvesm path "${storage}:${new_vol}" 2>&1) || true
    msg_error "Failed to resolve path for new volume: ${pvesm_error}"
    log "ERROR pvesm_path storage=$storage vol=$new_vol error=$pvesm_error"
    return 1
  fi
  mkdir -p "$(dirname "$storage_path")"
  truncate -s "${new_size}" "$storage_path"
  echo "${storage}:${new_vol}"
  ;;
```

### D. Fix `copy_data()` — capture dd errors (line 450)
The dd command sends progress to stdout but errors to stderr. The spinner captures stdout. Change to capture stderr separately:

```bash
copy_data() {
  local source_dev="$1"
  local dest_dev="$2"
  local source_size=$3

  local bs count
  read -r bs count <<< "$(get_dd_params "$source_size")"
  local dd_errors
  dd_errors=$(mktemp)
  dd if="$source_dev" of="$dest_dev" bs="$bs" count="$count" status=progress 2>"$dd_errors"
  local rc=$?
  if [[ $rc -ne 0 ]]; then
    cat "$dd_errors" >&2
    rm -f "$dd_errors"
    return $rc
  fi
  rm -f "$dd_errors"
  return 0
}
```
